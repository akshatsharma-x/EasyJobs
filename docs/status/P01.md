# P01 · Web app (`apps/web`, `@easyjobs/web`): status

**Done.** The web app is complete. `typecheck`, `test`, `build` and `e2e` all pass in mock mode. Three rounds of visual review were done at 1440×900 and 390×844 in light and dark, and the final screenshots are in `apps/web/screenshots/`.

## Summary

- **Stack:** Next.js 16.4 (App Router, RSC, Turbopack), React 19.3, Tailwind CSS v4, Radix/shadcn-style UI, TanStack Query v5, nuqs, cmdk, vaul, sonner, motion, zustand (persist), date-fns, lucide-react, next-themes, and Geist Sans + Geist Mono (subset, local).
- **Pages:**
  - `/`: hero search with autocomplete, quick chips, live strip, logo marquee, "Just posted" live feed (motion layout animation), category bento, top companies, batch band
  - `/jobs`: sticky search, level tabs with facet counts, filter sidebar / mobile vaul sheet, active chips, split view, infinite scroll, live "N new jobs" pill, smart search with undo, empty-state relaxations, keyboard shortcuts
  - `/jobs/[id]/[[...slug]]`: SSR job page with JSON-LD JobPosting, OG image, canonical URL, sticky apply CTA, "Also listed on", similar jobs, share/save/report, closed-job banner
  - `/companies` and `/companies/[slug]`
  - 5 SEO preset landing pages
  - `/saved`: Saved → Applied → Interviewing → Offer/Rejected tracker with notes and CSV export
  - `/about`, 404, error, loading states
  - `sitemap.xml`, `robots.txt`, `manifest.webmanifest`
- **⌘K palette:** search, presets, companies, pages, theme.
- **Data layer:** one `JobsApi` with two implementations. `http.ts` follows §0.5 exactly. `mock.ts` uses the same semantics: ~400 deterministic jobs, disjunctive facets, 3 sorts, suggest, stats, companies, and a simulated stream every 6–12 s. `NEXT_PUBLIC_USE_MOCKS` selects between them. Everything is imported from `@easyjobs/contract` and nothing is redefined.

## How to run

```bash
pnpm install
pnpm --filter @easyjobs/web dev            # http://localhost:3000, mock mode
pnpm --filter @easyjobs/web typecheck
pnpm --filter @easyjobs/web test           # vitest
pnpm --filter @easyjobs/web e2e            # builds, then runs Playwright on :3005
pnpm --filter @easyjobs/web screenshots    # 20 review screenshots → apps/web/screenshots/
```

**Real API:** set `NEXT_PUBLIC_USE_MOCKS=0` and `NEXT_PUBLIC_API_URL=http://localhost:4000` in the repo-root `.env`, then restart or rebuild. See `apps/web/README.md`.

## Decisions

1. **The URL format is the contract's.** Each key is parsed with `parseSearchQuery` and serialised with `toQueryString`. nuqs is used only for shallow, batched history updates. Preset and company pages merge their preset under the URL state, and a change made there navigates to `/jobs?…`. `?job=` (the split-view selection) uses replace history.
2. **Server render, then client refinements.** The server prefetches the first results page into TanStack Query (`HydrationBoundary`). After that, the client fetches with `keepPreviousData`, a 250 ms debounce on typing, and prefetching of job details on hover.
   - The default preview's description is *not* prefetched on the server: it is hidden on phones, and shipping it in every HTML response slowed mobile.
3. **Mock data stays fresh, deterministic and the same on server and client.**
   - Jobs store posting offsets that are turned into dates at query time.
   - Live (stream) ids are self-describing, so the server can render a job page for a job the browser only saw on the stream.
4. **Logos go through a same-origin `/logo/<domain>` proxy.** It tries logo.dev (if configured), then the Google favicon. Missing or low-res icons (< 32 px) return a 1×1 PNG, and the UI shows a monogram instead.
   - Pointing images straight at Google produced 404 console errors (for example tcs.com), which hurts Lighthouse Best Practices, and some icons were blurry.
   - This also keeps `LOGO_DEV_TOKEN` server-side.
5. **Correct HTTP status codes for job pages.** The job route has no `loading.tsx`, because streaming forces a 200, so `notFound()` returns a real 404 and wrong slugs get a 308 to `jobPath(job)`. The `/jobs` skeleton sits in a `(search)` route group so it only wraps the search page.
6. **Defence in depth.** Descriptions are sanitised again in the web app with `xss` (allow-list; h1/h2 demoted to h3; links get `rel="nofollow noopener"`). The sanitiser is lazy-loaded on the client.
7. **Performance choices, all measured:**
   - Native, accessible controls in the filters: `<details>`, checkboxes, a `role="switch"` checkbox, a range input and a `<select>` for sort.
   - Lazy-loaded vaul sheets, report dialog, sonner (`notify()` wrapper) and cmdk palette. motion only uses `LazyMotion` where layout animations live (the "Just posted" list, which loads after hydration, and `/saved`).
   - Subset variable fonts (68 KB → 36 KB each), both preloaded.
   - `experimental.turbopackChunking` set to fewer, larger chunks.
   - `inlineCss` was tried and rejected: Next duplicates the CSS twice into the RSC payload, which made the `/jobs` HTML 65 KB gzipped instead of 27 KB.
8. **Reports are stored locally.** The contract has no endpoint yet; see `docs/contract-requests/P01.md`.
9. **Wide 3-pane canvas.** `/jobs`, the presets and company pages use a 1440 px canvas (`container-wide`); content pages stay at 1280 px. The header width follows the page so the edges line up.

## Numbers

- **Unit tests:** 152 Vitest tests in 5 files, all passing. They cover:
  - mock API filters, disjunctive facets, sorts, pagination, closed jobs, regenerating live ids, and the stream
  - formatters: salary, time, experience, batches
  - the smart-query parser
  - the `toQueryString` ↔ `parseSearchQuery` round trip
  - the HTTP client against a stub §0.5 server
- **E2E:** 17 Playwright tests against the production build, all passing (15 desktop, 2 Pixel 7). They cover:
  - home search → results
  - smart chips and undo
  - level tabs, sidebar filters, URL, back/forward
  - chip removal, sort, empty state
  - split preview with j/k
  - job page JSON-LD, canonical and OG; 404 and 308
  - save persists after reload, tracker status, CSV
  - dark mode, ⌘K palette, `/` focus, presets, companies, sitemap/robots/404
  - mobile filter sheet; mobile card → full page
- **Lighthouse 12.8 mobile** (default simulated throttling, production build in mock mode, medians of 5 runs; Performance / Accessibility / Best Practices / SEO):

  | Page | HTTP/2 + TLS (`scripts/h2-proxy.mjs`) | Plain HTTP/1.1 (`next start`) |
  |---|---|---|
  | `/` | **99** / 100 / 100 / 100 | 94 / 100 / 100 / 100 (range 94–98) |
  | `/jobs` | **99** / 100 / 100 / 100 | 96 / 100 / 100 / 100 (range 94–98) |

  - CLS is 0.000 and TBT under 30 ms on every run. LCP is about 2.1–2.3 s on h2.
  - The HTTP/1.1 gap comes from Lantern modelling 6 connections per host; `next start` has no HTTP/2.
- **Payload:** the `/jobs` HTML is 27 KB gzipped. The two fonts are 36 KB each.
- **Mock speed (Node):** generating the dataset takes 8 ms; a search plus all 11 facets takes about 0.1 ms once warm; the UI shows `tookMs` ("62 jobs · 1 ms").
- **Mock dataset:** 400 open jobs from 45 companies and 34 sources. Levels: intern 92, fresher 86, entry 79, mid 70, senior 50, lead 14, executive 9. 71% official, 31% without salary, 118 posted in the last 24 h.
- **Build:** about 1–3 s compile plus about 3 s TypeScript.

## Known gaps

- **Not yet run against the real API**, because P02 isn't serving. The HTTP client is covered by a contract test against a stub server. **Port 4000 on this machine is held by an unrelated app** (`~/Downloads/temp5/outbox/backend`), so W1 must stop it or change `API_PORT` / `NEXT_PUBLIC_API_URL`.
- **Plain HTTP/1.1 Lighthouse on `/` has a median of 94, just under the 95 target.** Over HTTP/2, which is how a CDN or Vercel serves it, it's 99.
- **Reports aren't sent anywhere yet.** They're stored in localStorage until the API has an endpoint.
- **The home "Just posted" feed and `/saved` use motion layout animations.** Elsewhere I used CSS transitions to keep JS small: the level tab pill doesn't slide, and chips have enter animations only.
- **Live stream:** in mock mode it's simulated in the browser. In http mode it uses `EventSource` against `/v1/stream` and hasn't been tested end to end.
- **pnpm 12** prints `ERR_PNPM_IGNORED_BUILDS` (esbuild) on `pnpm add`, because the root `onlyBuiltDependencies` isn't honoured. See the contract requests.
