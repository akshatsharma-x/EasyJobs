# P10 · Internshala scraper — status

**Package:** `packages/scrapers/internshala` (`@easyjobs/scraper-internshala`) · **State:** done (see numbers below).

## Summary

Two `job_board` scrapers, both `intervalMinutes: 20`, exported from `src/index.ts` as `scrapers` (and `default`):

- `internshala-internships` — feeds `/internships/`, `/internships/work-from-home-internships/`, `/internships-for-women/`
- `internshala-jobs` — feeds `/jobs/`, `/jobs/work-from-home/`, `/fresher-jobs/`

They parse listing cards with cheerio, fetch detail pages (HTML + schema.org `JobPosting` JSON-LD) for unknown ids only,
capped per run, and emit contract `RawJob`s with full hints: `jobType`, `experienceLevel`, `experienceMin`, `workMode`,
`isRemote`, `salary` (stipend → month, CTC → year, unpaid, weekly, lump sum, performance-based), `skills`, `tags`
(`wfh`, `women`, `part-time`, `ppo`, `unpaid`), `validThrough` (apply-by), `postedAt`, `companyLogoUrl`, `companyDomain`,
`department`, and a rich `extra` (openings, perks, who can apply, CTC breakup, probation, start date, duration, PPO, …).
`applyUrl = sourceUrl =` the Internshala detail page. Discovery notes, selectors and the field mapping are in the package
README.

## How to run

```bash
pnpm --filter @easyjobs/scraper-internshala scrape --limit 30                    # both scrapers → packages/scrapers/internshala/out/*.jsonl
pnpm --filter @easyjobs/scraper-internshala scrape --scraper internshala-jobs --limit all --pages 3
pnpm --filter @easyjobs/scraper-internshala scrape --limit all --pages all       # backfill (≈ 300 listing pages per scraper)
pnpm --filter @easyjobs/scraper-internshala typecheck
pnpm --filter @easyjobs/scraper-internshala test                                 # offline; LIVE=1 adds a live smoke test
# dev tools (run inside the package): scripts/fetch-pages.ts · capture-fixtures.ts · inspect.ts · stats.ts · incremental-run.ts
```

The worker needs nothing special: it discovers `src/index.ts`, passes `ctx.isKnown` (incremental stop + light records)
and `ctx.http` (robots.txt, retries). The scrapers add their own process-wide ≥ 1.5 s throttle for internshala.com.

## Decisions

1. **robots.txt is obeyed literally.** Our UA falls under `User-Agent: *`. No query strings (`Disallow: /*?*`), no commas,
   never `/internship/details/`, `/job/details/`, `/api/`, `/…/search/`, `/external-jobs/`. Pagination is path-based
   (`/page-N/`), detail pages are the allowed singular `/internship/detail/…`. All fetches go through the contract client
   (runtime robots check); redirects are followed hop by hop so each hop is checked too.
2. **Politeness: ≤ 1 request / 1.5 s for the whole process.** A throttle shared by both scrapers (kept on `globalThis` so
   a worker re-import can't create a second one), on top of the contract client's limits and retries. 403/429 on a listing
   stops the run; on a detail page it stops detail fetching for the rest of that run.
3. **Several feeds per scraper.** Internshala has no newest-first sort and ranks in-office postings first — new WFH
   internships sit 100+ pages deep in `/internships/` — so WFH is crawled separately; `/internships-for-women/` adds the
   `women` tag; `/fresher-jobs/` makes sure fresher jobs are never missed. Ids already emitted in a run count as known, so
   overlapping feeds stop after a page or two. `/jobs-for-women/` is **not** used: it serves internship cards (found in
   the first live run — the crawler now warns and skips any feed whose page has no cards of its kind).
4. **Incremental stop** exactly as specified: each feed stops at the first page made entirely of known ids (configurable to
   N consecutive pages). Known cards on crawled pages are still emitted as light records (no description) so they stay
   "seen".
5. **Refresh rotation:** in incremental runs the main feed also re-reads 2 rotating deeper pages (cycling the whole list
   every ~1–2 days), so postings open for weeks don't hit the job-board "21 days unseen" closure. `target` is `null` and
   sweeps are not relied on (contract request #1).
6. **`sourceJobId` = the card's `internshipId`.** The detail URL ends with a (re)post Unix timestamp and changes on
   reposts; the timestamp is used for a precise `postedAt` when it agrees with the "posted" label.
7. **HTML first, JSON-LD second.** JSON-LD `JobPosting` is missing on some pages, so every field has an HTML source;
   JSON-LD fills `validThrough`, `department`, `industry`, organisation website/logo, months of experience and extra
   "who can apply" lines hidden from the logged-out HTML.
8. **Salary:** never invented. Unpaid = 0 (tag `unpaid`), Performance Based = `null`, weekly → monthly, lump sum spread
   over the duration (never over < 1 month). Original text in `salary.raw` / `salaryRaw`.
9. **Locations:** card cities as displayed (multi-city strings split, "(Hybrid)" removed → `workMode: hybrid`); WFH →
   `["Remote - India"]` (the JSON-LD address of WFH posts is the employer's office). International postings' "(City,
   Country)" suffix is moved out of the company name into `extra.companyLocation`.
10. **Unknown jobs over the detail cap** are emitted from their card with the preview as `descriptionText`; known jobs
    never carry `descriptionText`, so a stored full description is never replaced by a preview.

## Known gaps

- No server-side newest-first sort: a new posting ranked unusually deep can be missed by the incremental stop until the
  refresh rotation reaches its page (≤ ~2 days).
- Jobs emitted as light records because of the detail cap don't get their detail page later (they become "known").
  For the first backfill, raise `INTERNSHALA_MAX_DETAILS`.
- `women` tag (internships) is complete for detail-fetched and women-feed postings; light records first seen elsewhere may
  miss it. Jobs have no structured women signal (free-text "Female candidates preferred" is left to normalize).
- `experienceMax` is unknown (Internshala states only a minimum); `batches`/`degrees` are left to the normalizer (from the
  description's "who can apply" lines).
- Contract requests (sweep opt-out, Internshala URL ids, salary periods, `Unpaid` = 0, extra tags, WFH location, pnpm 12
  build approvals): `docs/contract-requests/P10.md`.
