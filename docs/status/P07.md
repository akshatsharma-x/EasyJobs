# P07 · Public ATS APIs — status

**Package:** `packages/scrapers/ats-public` (`@easyjobs/scraper-ats-public`) · **State:** done; typecheck, tests and LIVE smoke tests are green.

## Summary

Ten contract `Scraper`s, one per public ATS, each `kind: "ats"` with `handlesAts: [<ats>]`, driven by
`ctx.targets` (the worker passes one registry target per call):

| id | API (verified live 2026-11-26) | requests per board |
|---|---|---|
| greenhouse | Job Board API `boards/{token}/jobs?content=true&pay_transparency=true` | 1 |
| lever | Postings API `v0/postings/{site}?mode=json&limit=100&skip=n` (`eu:` → `api.eu.lever.co`) | ⌈n/100⌉ |
| ashby | Posting API `job-board/{token}?includeCompensation=true` | 1 |
| smartrecruiters | Posting API list (`limit=100&offset=n`) + detail for **unknown** postings | ⌈n/100⌉ + ≤ 200 |
| workable | widget API `widget/accounts/{account}?details=true` (chosen over v3, see Decisions) | 1 |
| recruitee | Careers Site API `{company}.recruitee.com/api/offers/` | 1 |
| bamboohr | `{company}.bamboohr.com/careers/list` + `/careers/{id}/detail` for unknown postings | 1 + ≤ 200 |
| personio | XML feed `{company}.jobs.personio.de/xml?language=en` (+ default-language feed when needed) | 1–2 |
| breezy | `{company}.breezy.hr/json?verbose=true` | 1 |
| teamtailor | career-site RSS `jobs.rss?per_page=100&offset=n` | ⌈n/100⌉ |

All four "if time permits" ATSs (BambooHR, Personio, Breezy, Teamtailor) are done. 48 real, live, verified fixture
targets (5 per ATS, 3 for Breezy) are in `src/fixtures/targets.ts`; 22 of them are Indian companies or hire in India; together they list 5,750 open jobs.

## How to run

```bash
pnpm --filter @easyjobs/scraper-ats-public scrape --limit 30                  # all ATSs over the fixture targets
pnpm --filter @easyjobs/scraper-ats-public scrape --scraper lever --limit all
pnpm --filter @easyjobs/scraper-ats-public test                               # offline (saved fixtures)
LIVE=1 pnpm --filter @easyjobs/scraper-ats-public test:live                   # one smoke test per ATS
pnpm --filter @easyjobs/scraper-ats-public verify-targets [--write]           # board sizes of the fixture targets
pnpm --filter @easyjobs/scraper-ats-public report                             # counts + fill rates → out/report.md
pnpm --filter @easyjobs/scraper-ats-public fixtures [ats]                     # re-capture fixtures (cached in .cache/)
```

## Decisions

- **Every hint is from structured source fields only** (employment type, workplace, level, salary, years). Keyword
  detection stays in the normalizer (P03), and hints override it, so mappings are conservative: broad labels such as
  "Mid-Senior level"/"Experienced" give `mid` only when the title has no seniority words, and ambiguous employment
  labels ("Full Time/Part Time") give none.
- **`applyUrl` = `sourceUrl` = the official posting page.** The ATS's application-form URL goes in `extra.applyFormUrl`.
  `company`/`companySlug`/`companyDomain` come from the registry target.
- **`ctx.since` is ignored**, because the worker sweeps `(source, target)` after complete runs and any job not emitted
  would be closed. Boards cost 1–10 requests anyway. Contract request #1 proposes a cheap "seen" channel.
- **List+detail APIs (SmartRecruiters, BambooHR):** known postings → light records without detail calls. Unknown
  postings beyond `ATS_MAX_DETAILS` (200), or after a 429/403 or 5 failures in a row, are **deferred**, not emitted:
  they aren't stored yet, so no sweep can close them, and the next run fetches them. SmartRecruiters lists newest
  first, so fresh postings get details first. Optional registry hint `extra.country: "in"` filters huge MNC boards
  server-side (Bosch: 5,171 worldwide → 687 India).
- **Workable:** widget API (1 request per board, with descriptions) rather than v3 (no descriptions, pages of ~10,
  plus one v2 request per job). Its quirk of one entry per location is merged by shortcode; that matches the v3
  totals exactly (66/58/51/79 on four accounts). Trade-off: no hybrid/on-site distinction, only `telecommuting`.
- **robots.txt:** skipped (`robots: false`) for the documented JSON APIs (Greenhouse, Lever, Ashby, SmartRecruiters,
  Workable, Recruitee); **respected** on company career hosts (BambooHR, Personio, Breezy, Teamtailor). A robots
  opt-out is treated like a dead board. Polestar's Teamtailor site (`Disallow: /`) was dropped from the fixtures
  for that reason.
- **Dead boards** (404/410 on the first request; BambooHR's 302 to its home page) are logged once and the target
  finishes cleanly. The same error after jobs were emitted, or a malformed 200 (HTML, `{}`), fails the target: a
  partial run must never be swept. Other errors also fail the target: with one target the original `HttpError` is
  rethrown, and with several, every target still runs and one aggregated error is thrown at the end.
- **`ctx.limit` is shared fairly across targets**, with unused share rolling over, so `--limit 50` exercises all 5
  targets. Pagination is lazy, so a limit costs no extra pages.
- **Salaries are never invented.** 0–0 and placeholder ranges are dropped; a period comes only from the API or an
  unambiguous magnitude. Greenhouse ranges have no interval field, so I use "Annual"/"Monthly" in the range title,
  ≤ $200 → hour, ≥ $10k → year, and otherwise only `salaryRaw`. Amounts must also be plausible for the period, for
  every ATS: Databricks labels some yearly ranges "SF Bay Area Hourly Rate" (USD 222,500 "per hour"), and other
  ranges are data-entry errors ("USD 170–256"). INR is preferred when a job lists several currencies.
- **Privacy:** SmartRecruiters `creator` is never read. Greenhouse metadata is reduced to the fields we map, because
  one board exposed an employee email in a "Backfill ID" field. Email/phone-like values are dropped, and Personio
  "Contact" sections are cut from descriptions.

### Benchmarks

- One-request boards are fast: all 5 Greenhouse boards (1,197 jobs with full HTML descriptions) in 9.0 s, and 5
  Ashby boards in 3.3 s.
- List+detail APIs are bound by politeness: ~1.3 requests/s per host, so 200 SmartRecruiters details take ≈155 s.
  The worker's default per-task timeout (30 min) leaves ample room.
- `pnpm --filter @easyjobs/scraper-ats-public test`: 251 tests in ≈0.4 s. `LIVE=1 … test:live`: 10/10 pass in 29 s.

## Tests

`pnpm --filter @easyjobs/scraper-ats-public test` runs 251 offline tests in 13 files (≈0.4 s), plus 10 LIVE=1 smoke tests:

- Parser tests per ATS on saved, trimmed real fixtures (`test/fixtures/<ats>/`, 248 KB; `manifest.json` maps each
  edge case to a posting id). Edge cases: remote-only, multi-location (Workable duplicates, Lever `allLocations`,
  Ashby secondary locations, Greenhouse `;` lists, Teamtailor `tt:locations`), salary present/absent/placeholder/
  hourly/monthly/open-ended, internships (metadata, commitment, ids, Werkstudent), Ausbildung, hybrid, custom
  career domains, German-only Personio boards, light records, dead boards, robots opt-outs.
- Pagination with mocked responses: Lever (`skip`, exact multiples, duplicates across pages, `skip` ignored, lazy
  with a limit), SmartRecruiters (`totalFound` and the country filter), Teamtailor (`offset`, `offset` ignored), and
  the generic paginator's total and safety cap.
- Runner: fair-share limits, other-ATS targets, dead boards, single vs aggregated failures, abort, duplicates, kill
  switch. Detail budget: cap, 429 and 5 failures in a row.
- Table-driven helper tests: employment type, workplace, level, dates, locations, HTML, salary periods/parsing/
  plausibility, privacy.
- Malformed 200s (`{}`, HTML) fail every adapter with `UnexpectedResponseError` rather than reading as an empty
  board, which would make the worker close every stored job.

## Known gaps

- **Workable** has no hybrid/on-site distinction (widget only exposes `telecommuting`); remote is reliable.
- **SmartRecruiters** can't tell an unknown company id from an empty board (both 200 + `totalFound: 0`); logged.
- **Big list+detail boards fill in over several runs**: ServiceNow (972), NielsenIQ (435), Experian (416) and
  Bosch-India (687) emit 200 detailed postings per run until caught up (~5 hourly runs). Raise `ATS_MAX_DETAILS`
  for a faster first sync.
- **Departments are passed through as published**: e.g. InMobi's Greenhouse departments are named after managers.
- **Recruitee/Breezy/BambooHR/Personio targets have no India presence**; these ATSs are mostly used by European and
  US SMBs. The adapters work for any registry entry.
- **Greenhouse/Personio/Teamtailor have no structured experience level** unless a board adds metadata; the
  normalizer's title rules cover them.
- **Location strings stay raw** (with the country appended when structured data provides it); city canonicalisation
  is P03's job. See contract request #4.
- **`companyLogoUrl`** comes only from Breezy or `target.extra.logoUrl`; the normalizer's domain-based logos cover
  the rest.
