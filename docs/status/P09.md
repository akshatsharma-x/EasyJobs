## How to run

```bash
pnpm --filter @easyjobs/scraper-bigtech scrape --scraper amazon --limit 50      # → packages/scrapers/bigtech/out/amazon.jsonl
pnpm --filter @easyjobs/scraper-bigtech scrape --limit 20                       # every enabled company
pnpm --filter @easyjobs/scraper-bigtech test                                    # offline, fixtures only
LIVE=1 pnpm --filter @easyjobs/scraper-bigtech test                             # + one live smoke test per enabled company
cd packages/scrapers/bigtech && npx tsx scripts/report.ts --limit 50 --opt-in   # the table below
```

The worker discovers the package automatically (`src/index.ts` exports `scrapers` / `default`).

## Decisions

1. **One factory for run semantics** (`src/lib/site.ts`):
   - Flow: list → detail only for ids `ctx.isKnown()` doesn't know (capped per run) → map → `validateRawJob`.
   - Unknown jobs over the detail cap are **deferred** to the next run; they are not emitted without a description.
   - Known jobs are emitted as light records, so sweeps see them as open.
   - **`ctx.since` is never used to drop jobs**, because the worker would sweep them closed. Filed as contract request #1.
   - Jobs dropped after a detail fetch (closed, abroad) go into an in-process memo (24 h), so incremental runs don't re-fetch them.
2. **Politeness:**
   - Only the contract HTTP client, with the honest UA and robots.txt always enforced. No scraper sets `robots: false`.
   - A per-host gap of ≥ 1 s (≤ 1 rps); Microsoft uses 15 s, and the env var can only raise a site's floor.
   - Page sizes ≤ 50; exponential back-off on 429.
   - No login, cookies, session/CSRF tokens, challenge solving or proxies.
   - Playwright (`scripts/capture.ts`, local Chrome) was used for endpoint discovery only.
3. **What counts as "plain board" (registry, not built here):** Greenhouse, Lever, Workday, Oracle, Eightfold v2,
   SmartRecruiters and Ashby, which P07/P08 read as-is. Two exceptions are built here anyway because the plain-adapter
   path fails:
   - **Microsoft:** Eightfold PCSX answers P08's v2 API with 403.
   - **Accenture:** Workday cxs ignores offsets ≥ 2,000, which is about 6% of India's jobs.

   Sites on iCIMS, Avature, SuccessFactors, Phenom, RippleHire and Zoho Recruit are built here.
4. **Infosys is opt-in.** The website returns a 403 to our bot UA, but the JSON gateway is open. Following the project's
   LinkedIn/Naukri precedent, it is off by default and the operator decides.
5. **Accenture scope.** A full India crawl is about 25k jobs × 13 KB per run. The default scope is the complete
   "0–2 years" band, which is the EasyJobs core audience and keeps sweeps correct. `ACCENTURE_EXPERIENCE` widens it.
6. **Google** reads the public jobs XML feed. Verified with the contract's robots parser: for `*`, only `?page=` paging is
   disallowed; the `/jobs/results` disallow belongs to the Yandex group.
7. **Apple** reads the hydration JSON embedded in its pages; its JSON API needs a per-session CSRF token.
8. **Mapping conventions:**
   - `applyUrl = sourceUrl` = the official job page; hash-routed SPAs also get a unique query param.
   - `target = companySlug = id`.
   - Locations are readable ("Bengaluru, Karnataka, India").
   - Level hints come only from the site's own categories and are left unset when vague (Microsoft's model-inferred
     facet is deliberately ignored).

## Known gaps

- **Microsoft** rate-limits by IP at about 5 requests/min with a long penalty window. Consequences:
  - A run takes about 6–14 min.
  - Backfill is 30 details per run, so all 232 jobs need about 8 hourly runs.
  - If 429s persist through the 30 → 60 → 120 s back-off, the run fails (no sweep) and the worker's back-off takes over.
- **Detail-less fields:**
  - HCLTech job pages have no posting date, so `postedAt` is null and falls back to first-seen.
  - Atlassian has no posting date, so `postedAt` uses iCIMS `updatedDate`.
  - Wipro's sitemap lags about 5 days.
  - IBM job pages sit behind an AWS WAF challenge, so IBM is list-only; its list carries the full description.
- **Experience-level hints** are sparse by design: most sites have no reliable career-stage category, and the normalizer
  derives levels from titles and years.
- **Disabled targets** (Meta, Uber, Flipkart, TCS, Tech Mahindra, Cognizant) need permission, a feed or an open ATS
  board to come back. Each module documents what was tried. TCS keeps a tested parser for a captured response.
- **Cleanup:** RippleHire is implemented twice (`ltimindtree.ts` and the shared `_ripplehire.ts`), and the detail cap
  counts `detail()` calls rather than HTTP requests.
