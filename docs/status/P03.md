# P03 · Normalizer and enrichment: status

Package: `packages/normalize` (`@easyjobs/normalize`). It turns any `RawJob` into a validated `JobInput` (§0.4).

## Summary

**DONE criteria, all met:**
- Typecheck is clean.
- **879 tests in 16 files** are green. They run offline in about 4 s and include the fuzz and perf suites.
- Fixtures cover every rule (see "Rule coverage" below).
- This file, `packages/normalize/README.md` and `.env.example` are written.

**API:**
- `normalizeJob(raw, { sourceName?, company?, now? })`.
- The 23 functions the prompt names are exported and unit-tested one by one, plus `*Detailed` variants that also return confidence and source.
- Everything is pure, synchronous and deterministic given `now`, except the optional `enrichWithLLM`.

**Never throws:**
- The output always passes `validateJobInput`.
- The fuzz suite covers 5,000 garbage or corrupted RawJobs, non-object inputs, odd options, and every documented step function called with odd values in every argument.

**Real data:**
- 8,037 RawJobs from 66 output files of P05–P12 (read-only): 0 invalid, 0 unparseable lines.
- A re-run with the same `--now` is byte-identical.

**Worker:** P05's `smokeTestNormalizer` passes against `normalizeJob`. The worker picks this package up automatically instead of `fallback-normalize.ts`, with nothing to change.

**Throughput:**
- The ≥ 5k jobs/s target held on the synthetic mixed corpus: 7.4k jobs/s wall-clock at 06:24, at load average 6.4. Later the machine began swapping because of other sessions, and the same code dropped to 1.6–5.0k. The 5k gate is therefore `run bench`, not the default test run (Known gaps #9).
- Real postings with full-length descriptions (about 5 KB on average) run at about 2.1–2.5k jobs/s. See Known gaps.

**LLM:** `enrichWithLLM` (`claude-haiku-5-5`, strict tool use, disk cache) does nothing without `ANTHROPIC_API_KEY`. It was tested with a fake client only.

## How to run

```bash
pnpm --filter @easyjobs/normalize typecheck
pnpm --filter @easyjobs/normalize test                 # offline; PERF_MIN_JOBS_PER_SEC=5000 also enforces the 5k target
pnpm --filter @easyjobs/normalize run bench            # throughput; exits 1 below 5,000 jobs/s (the perf gate)
pnpm --filter @easyjobs/normalize run cli packages/scrapers/coursejoiner/out/coursejoiner.jsonl > /tmp/jobs.jsonl
pnpm -s --filter @easyjobs/normalize run cli $(ls packages/scrapers/*/out/*.jsonl) --stats-only --now 2026-11-26T00:00:00Z
```

- **Output:** JobInput JSONL goes to stdout; distributions go to stderr. pnpm 12 also writes its script banner to stderr, so stdout stays clean JSONL.
- **Options:** `--now`, `--source-name`, `--llm`, `--llm-max <n>`, `--stats-only`, `--out <file>`, `--top <n>`, `-` for stdin.
- **Exit codes:** 1 if any output fails `validateJobInput`, 2 on bad arguments or an unreadable file.

## Integration notes for W1

1. **Worker:** no changes needed (the smoke test passes). P05 noted that its fallback's fingerprints match §0.4 only for Greenhouse, Lever, Ashby, Workday and canonical URLs. A dev database filled by the fallback may therefore get a few duplicates after the switch; reset dev data.
2. **Registry:** pass the registry entry as `opts.company` (e.g. `findCompany()` from `@easyjobs/registry`). Its name, slug, domain and tags win over scraped values, and `companyTags` come only from it. Without it, the built-in alias table (219 companies) resolves names, and `companySlug = slugify(name)`, which matches P04's slugs.
3. **API merge (§0.4):** two signals help the merge.
   - `extra.normalize.defaulted` lists fields that hold a default rather than evidence (`experienceLevel`, `jobType`, `category`). A higher-priority source should not overwrite a stored real value with one of those.
   - `extra.light: true` marks re-sightings without a description: copied from the scraper, or set when there is no description at all. The merge should keep stored description-derived fields (level, category, skills, degrees, summary, qualityScore) for those.
   - Contract request #1 formalizes both.
4. **Confidence and provenance:**
   - `extra.normalize.confidence.{level,category}` is `high`, `medium` or `low`.
   - `extra.normalize.sources` says where level, jobType, workMode and experience came from.
   - `extra.normalize.fingerprintRule` is `k` or `t`; `warnings` lists repaired input; `version` is `1.0.0`.
   - Bump `NORMALIZER_VERSION` when rules change, so stored jobs can be re-normalized.
5. **Enrichment:**
   - When: optional and async. Call it after `normalizeJob` and before ingest, ideally only for new fingerprints.
   - Concurrency: `enrichManyWithLLM(jobs, { concurrency })`.
   - Budget: `cacheOnly: true` keeps applying cached answers once a budget is spent. Never call it on light records.
6. **Determinism:** pass `now` (the run start). Relative dates ("2 days ago"), recency points and fallbacks then stay stable within a run.

## Decisions

### Identity and dedupe

1. **Fingerprint rule 1 requires an official *and* job-specific apply URL** (P06 #3).
   - Problem: a blog linking `infosys.com/careers/` would otherwise give every Infosys post the same key.
   - `isJobSpecificUrl` asks for an ATS key, a job-id-like path segment or query parameter, or a job slug.
   - `RawJob.extra.applyUrlSpecific` (P06) overrides the heuristic.
   - Rule 2 uses `companySlug | titleKey | primary city or "remote" | jobType`. `titleKey` folds noise and synonyms (Sr. → senior, SDE → software development engineer, 2 → ii, …).
2. **`canonicalUrl` keeps SPA hash routes (`#/…`, `#!/…`)**, even though §0.4 says "no hash". Superset's `#/…/jobprofiles/<uuid>` routes otherwise collapsed 5 different jobs into one. Every other hash is dropped. Contract request #3.
3. **`canonicalJobKey` covers 31 key families:**
   - Every listed ATS and board: Greenhouse (`gh_jid`, boards, embeds, API, EU), Lever (incl. EU), Ashby (`ashby_jid`), SmartRecruiters, Workable, Workday (tenant + JR id, `myworkdaysite`), Oracle, Eightfold (`pid`), amazon.jobs, Google, Microsoft, Internshala, LinkedIn (`/jobs/view`, `currentJobId`), Naukri and Unstop.
   - Others: Recruitee, BambooHR, Breezy, Personio, Teamtailor, iCIMS, Jobvite, Taleo, SuccessFactors, Darwinbox, Keka, Freshteam, Wellfound, Indeed, Glassdoor and Superset.
   - Everything else falls back to `canonicalUrl`.
   - Internshala: the URL's trailing 10 digits are the repost time, not an id (P10 #2), so the key is the slug. internshala.com is a job-board host, so fingerprints use rule 2 anyway.
4. **Host lists** in `src/data/hosts.ts`: 59 ATS hosts, 103 job-board/aggregator hosts and 41 non-official hosts (shorteners, forms, messengers, document hosts, `.invalid`). Rule 1 applies only to hosts outside the job-board and non-official lists. `google.com/url?q=` redirect links count as non-official, while other google.com paths (Google Careers) stay official. No such links appear in the real corpus.
5. **Garbage URLs become `https://unknown.invalid/<source>/<id>`**, so the output always validates. Such hosts are never official.

### Facts (hints win)

6. **Hints win, after cleaning.**
   - Valid enum hints (`jobType`, `experienceLevel`, `workMode`) are used as-is; invalid ones are ignored.
   - `salary` hints are validated: numeric, min ≤ max, plausible.
   - `batches` must be plausible years. Skills are canonicalized against the dictionary; unknown ones are kept in Title Case, capped at 12.
   - Degrees are mapped onto the canonical labels (`HINT_ALIASES` covers the P06/P12 vocabulary).
   - When a source sends skill or degree hints, they are used **instead of** extraction.
7. **Level precedence (§0.4, made precise):**
   1. `jobType: internship` → intern.
   2. Years from a structured field, `experienceRaw` or the title → years mapping. Exception: an executive title (Director/VP/Head/Chief) with ≥ 5 years stays executive.
   3. The structured hint.
   4. Years found only in the description, unless a strong title disagrees ("Senior Engineer" + "2+ years of React" stays senior).
   5. Title keywords: the full prompt vocabulary, Intern through Chief, including L3–L7, SDE I/II/III and Engineer 1/2/3. Meta-style E-levels and IC-levels are not mapped; they mean different things at different companies.
   6. Apprenticeship → fresher.
   7. Description fresher phrases or batches → fresher.
   8. Description entry phrases → entry.
   9. Default `entry` with **low** confidence, also listed in `defaulted`.
   - Fresher words with max years ≤ 2 → fresher, per §0.4.
   - Description-derived years rank below the hint because they are often about a single skill.
8. **Experience:**
   - "N years", "N+ years" and "minimum N" → `{ min: N, max: null }`. "Freshers" → `{0, 0}`. "fresher/experienced" → `{0, null}`.
   - Free text is parsed in strict mode: it needs years/experience wording in the same clause, and skips degree durations ("4-year B.Tech") and company age.
   - Month-only figures in titles are durations ("6 months internship"), not experience.
   - Maximum 50 years.
9. **Salary: never invented.**
   - "Not disclosed", "Competitive" and "Performance based" → `null`.
   - "Unpaid" → 0/0, kept as a real zero (`salaryInrYearly* = 0`, P10 #4).
   - Indian formats: LPA, lakh, crore, K, `/month`, ranges with Indian digit grouping.
   - INR/year conversion: month ×12, hour ×2080. Day and week pay become monthly first (×22, ×52/12), because `Salary.period` has neither (contract request #4).
   - Static FX table: 51 currencies, as of 2026-11.
   - Results outside ₹5,000–₹20 Cr per year are dropped as implausible.
10. **Locations:**
    - **Alias tables:** 199 Indian and 229 global cities (885 aliases), 19 secondary cities, 111 states/provinces and 80 countries.
    - **Canonical names:** Bengaluru, Gurugram, Mumbai (incl. Navi Mumbai and Bombay), Hyderabad (incl. Secunderabad), Noida (incl. Greater Noida), Delhi (incl. New Delhi and Delhi NCR), Kochi and Thiruvananthapuram.
    - **Splitting:** multi-city strings are split on `/ | ; , or & and`, and the parts are grouped back into city/state/country.
    - **Special strings:** "Pan India" → country IN (multiple); "Multiple locations" → multiple, no city; "Anywhere"/"Remote" → remote; "Remote - India" → remote, IN, no city (P10 #6); "Hybrid - Pune" → Pune + hybrid.
    - **"CA":** California unless the context is Canadian ("Toronto, CA" → Canada).
    - **workMode order:** hint → location strings → title → employment type → tags → description windows around remote/hybrid/WFH anchors. `isRemote` = remote.
11. **Skills:**
    - **Dictionary:** 694 skills in 27 groups, in `Name :: alias|alias` format.
    - **Matching:** token-based and boundary-safe. Context markers handle ambiguous words: `~` needs capitalization (Go, Swift, Spring), `=` needs upper case (R, CAN), `!` needs a list or strong context (Recruitment, Networking).
    - **Real-data rules:**
      - "AI" counts as a skill only next to an ML/data skill.
      - The company's own name is never its skill ("Postman" on Postman's postings).
      - Benefits wording ("compensation and benefits", "learning and development") counts only in skill lists.
    - **Ranking:** title skills first, then frequency, max 12.
    - **Soft skills:** at most 2, and only when fewer than 6 hard skills were found.
12. **Batches:**
    - Years must appear in batch or graduation wording: batch, passouts, YOP, graduating in, class of, eligible….
    - The window is now−8 to now+6.
    - A span of 3–5 years is a degree duration, so only its end year counts. Spans ≤ 2 are expanded.
    - Unrelated years ("since 2005", "© 2026") are ignored.
13. **Degrees:** 30 labels, aligned with P06/P12 (contract request #2).
    - Bachelor's: B.E/B.Tech, BCA, B.Sc, BBA, B.Com, BA, B.Pharm, B.Arch, B.Des, LLB, MBBS.
    - Master's: M.E/M.Tech, MCA, M.Sc, MBA, M.Com, MA, M.Pharm, LLM.
    - Other: Diploma, PhD, Any graduate, Any postgraduate, Bachelor's, Master's, 12th Pass, 10th Pass, ITI, CA, CFA.
    - "BS/MS" → B.Sc/M.Sc, and PGDM → MBA. LLM counts as the law degree only as "LL.M" or in a law context. Short codes (BE, CA, MS…) are case-sensitive.
14. **Category:** weighted title rules, including German, Portuguese and Norwegian titles, then department rules, then skill-group votes (capped). `other` is used when nothing scores, and is listed in `defaulted`.

### Text, dates, tags, quality

15. **Titles and companies:**
    - `cleanTitle` strips "Hiring!!", "Urgent", "Off Campus Drive 2026", batch suffixes, "| Apply Now", emoji, the company name and trailing location suffixes ("- Bangalore", "(Pune)"). When a RawJob has no locations, they are recovered from those title parts.
    - `resolveCompany` covers legal suffixes, regions and aliases ("Amazon Development Centre (India) Pvt. Ltd." → Amazon, "Tata Consultancy Services" → TCS, One97 → Paytm, Bundl → Swiggy).
16. **Logo order:** logo.dev (with a token) → a stable source logo (licdn, fbcdn, googleusercontent and cdninstagram URLs are skipped because they expire) → the Google favicon → `null` without a domain.
17. **Description:**
    - sanitize-html with the prompt's allowlist; double-escaped HTML is decoded; scripts, styles, iframes, pixels and empty paragraphs are removed.
    - Links get `rel="nofollow noopener noreferrer" target="_blank"` and relative links are resolved against `sourceUrl`.
    - Plain-text descriptions become simple HTML.
    - `summarize` prefers the "About the role" section and cuts at a sentence boundary (≤ 280 chars).
18. **Dates:**
    - Formats: ISO, epoch seconds or milliseconds, RFC 2822, "Posted Today", "Just now", "2 days ago", "30+ Days Ago", "Posted on 12 Nov 2025".
    - Numeric dates are read DD/MM unless only MM/DD is possible.
    - Missing, garbage, pre-1995 or future values → `now`.
19. **Tags:** off-campus, walk-in, wfh, women, diversity, pwd, urgent, test-posting and suspicious. Cleaned scraper hint tags are added (unpaid, ppo, part-time, …).
    - **wfh** goes on every remote job.
    - **women** and **pwd** need hiring intent: EEO and inclusion boilerplate don't count.
    - **walk-in** needs "walk-in" or "walk in interview/drive".
    - **suspicious** comes from the scam signals below.
20. **Scam signals behind `suspicious`:**
    - **Fees:** a registration, training or security fee with an amount, or "pay to apply". Disclaimers ("we never charge", "₹0 (FREE)") and service-bond clauses don't count.
    - **Contact:** WhatsApp/Telegram-only contact, unless the job has an official apply link. Messenger apply links. Gmail/Yahoo recruiter addresses.
    - **Too good to be true:** "earn ₹5000 per day", or a paid course with a job guarantee.
    - **Unrealistic pay:** INR pay above ₹40 L/yr for freshers or ₹30 L/yr for interns, from non-official sources.
21. **qualityScore:**
    - Points: official source 25; apply URL up to 20 (official and specific 20, official generic 12, job board 8, job board that is just the source page 4, other 2); description length up to 20; salary 10; location or remote 10; recency up to 15 (≤ 3 days 15 … ≤ 60 days 3).
    - Penalties: suspicious −40, test-posting −80. The result is clamped to 0–100.

### Robustness and performance

22. **Robustness:**
    - `normalizeJob` wraps everything; on an unexpected error it returns a minimal valid JobInput with `extra.normalize.error`, and the fuzz suite asserts that this never happens.
    - The step functions accept `null`, wrong shapes and invalid `now`.
    - Inputs are capped: titles 1,000 chars, descriptions scanned up to 12–20K chars per rule, dates 300 chars.
23. **Performance:**
    - Every regex is linear: bounded repetitions, lookbehind-anchored runs, keyword gates before expensive passes, and windows around anchors.
    - The skill tokenizer is regex-based on purpose. `RegExp.exec` flattens V8 rope strings, while a `charCodeAt` loop over a rope was super-linear (about 700 ms on one long description).
    - URL parsing is memoized (512 entries).
24. **LLM design:**
    - Runs only for low-confidence records: defaulted level, low-confidence or `other` category, or no skills, with ≥ 120 chars of text.
    - One forced tool call, `strict: true`, effort `low`, `max_tokens` 1024; the system prompt treats the posting as data.
    - Output is validated again (enums, canonical skills and degrees, year bounds).
    - It fills only weak or empty fields, and copies `title`, `company`, `applyUrl` and `fingerprint` back unchanged.
    - Cache: one JSON file per fingerprint, keyed by model.
    - Failures: refusal, `max_tokens`, invalid output and API errors return the job unchanged. Authentication and permission errors disable enrichment for the process.

## Known gaps

1. **Real throughput is below 5k jobs/s for full-length descriptions:** about 2.5k jobs/s on the real corpus. Cost grows linearly with description size (about 80 µs/KB). If ingest volume needs more:
   - skip re-normalizing unchanged descriptions (hash `descriptionHtml`);
   - mark known jobs as light records (26k/s);
   - normalize in a worker-thread pool.
2. **The FX table is static** (as of 2026-11). Update `src/data/fx.ts` periodically, or have W1 inject live rates.
3. **Non-English postings are handled only partly.** Category rules know common German, Portuguese and Norwegian titles. JS `\b` treats non-ASCII letters as word boundaries; known traps are guarded ("alguém com" is not M.Com), but rare false matches are possible in other languages.
4. **Hint quality is inherited.**
   - "Communication" is the top skill, mostly from Unstop and Internshala skill hints.
   - Unstop's eligible-course lists are trusted as degree hints. They often list every course: 328 of the 355 jobs with "CA" come from there.
   - Hints win per the prompt. W1 may prefer extraction for specific sources.
5. **Many ATS levels rest on weak evidence:** only 38% of ATS records have a high-confidence level, because many titles carry no seniority and ATSs send no level. 902 jobs (11%) default to `entry`, and 1,780 default to `full_time`. All are flagged in `defaulted` and are what `enrichWithLLM` targets.
6. **Scam pay thresholds are India-centric:** only INR salaries from non-official sources are checked.
7. **The LLM path was never run against the live API** (no key here). It was tested with a fake client against the SDK 1.14 types.
8. **Light records and `defaulted` only help once the API merge honors them** (contract request #1).
9. **Absolute throughput depends on the machine's state, so the 5k gate is not part of the default test run.**
   - On this shared machine the same code measured 7,466 jobs per CPU-second at 06:24 and 1,572 at 06:52. By then other sessions had pushed it to 27 GB of swap and a 20 GB memory compressor.
   - An A/B run of the code before and after the input guards matched within noise (ratio 0.98), so the drop was not a regression.
   - `pnpm test` therefore reports the 5k target and asserts a 500 jobs/s sanity floor. `run bench` exits 1 below 5k, and `PERF_MIN_JOBS_PER_SEC=5000` makes the test strict.
