# P06 · Scraper: CourseJoiner (+ similar fresher job blogs) — status

Package: `packages/scrapers/coursejoiner` (`@easyjobs/scraper-coursejoiner`). Details are in its `README.md`.

## Summary
- **4 scrapers**, all built from one generic `createWpJobBlogScraper({ id, name, baseUrl, includeCategories, excludeCategories, … })`:
  - `coursejoiner`
  - `freshershunt`
  - `fresheroffcampus`
  - `kickcharm`
- All are `kind: "aggregator"`, `intervalMinutes: 15`, with attribution "Jobs via <Site>".
- Each was verified on 2026-11-26: robots.txt allows the exact REST URLs we request, and the public WP REST API is on.
- Data path: WP REST (preferred) → RSS (conditional GET) → HTML (sitemap + page, cheerio) fallback. Everything runs through the contract HTTP client (robots.txt, retries, backoff) plus a per-host gate: one request in flight and ≥ 1 s apart.
- **Parsing**: tolerant "Label: value" extraction from tables, `<strong>` lines, plain lines and `<br>` paragraphs. Then:
  - company (KV, "About X" heading, title, tags, lead sentence)
  - apply-link scoring (ATS/company/job-specific paths preferred; social/Telegram/WhatsApp/other blogs rejected; wrappers unwrapped; tinyurl/bit.ly resolved and cached)
  - role(s) and hints
  - cleaned `descriptionHtml`
- **Multi-role**: posts become one RawJob per role (`<postId>#<n>`) via role tables, role-naming apply anchors or city-specific apply links.
- **Incremental**: `ctx.since` → `modified_after`; full window (default 60 days, `--backfill-days`) on the first run, from the CLI, and on worker full runs.
  - Unchanged posts are served from a parse cache (no refetch, no re-parse).
  - With `ctx.isKnown` they are emitted as light records (`descriptionHtml: null`, `extra.light: true`).
  - `ctx.limit` is honoured, and jobs whose deadline passed are not emitted.
- **Optional LLM**: `claude-haiku-5-5`, strict JSON schema, used only for low-confidence posts when `ANTHROPIC_API_KEY` is set. It can only pick apply links from our candidates, by index. Results are cached by post id + modified date, with at most 30 calls per run. Everything works without it.

## How to run
```bash
pnpm --filter @easyjobs/scraper-coursejoiner scrape --limit 100      # DONE check (all 4 sites → packages/scrapers/coursejoiner/out/*.jsonl)
pnpm --filter @easyjobs/scraper-coursejoiner scrape --scraper coursejoiner --limit all --backfill-days 60
pnpm --filter @easyjobs/scraper-coursejoiner scrape --since 6h       # incremental mode
pnpm --filter @easyjobs/scraper-coursejoiner stats out --markdown    # the tables below
pnpm --filter @easyjobs/scraper-coursejoiner typecheck
pnpm --filter @easyjobs/scraper-coursejoiner test                    # offline
LIVE=1 pnpm --filter @easyjobs/scraper-coursejoiner test             # + live smoke test per site
pnpm --filter @easyjobs/scraper-coursejoiner discover <host>         # vet a new blog
```
The worker discovers `src/index.ts` (`export const scrapers` and `export default`). No targets are needed: all jobs have `target: null`.

## Env vars
- `SCRAPER_USER_AGENT` — bot UA.
- `ENABLE_COURSEJOINER|FRESHERSHUNT|FRESHEROFFCAMPUS|KICKCHARM` — set `0` to disable a site.
- `WPJOBS_BACKFILL_DAYS` (60), or per site `<ID>_BACKFILL_DAYS`.
- `WPJOBS_REFRESH_HOURS` (24) — a full-window refresh even if the caller always passes `since`.
- `WPJOBS_CACHE_DIR` (package `.cache/`; `off` = memory only).
- `ANTHROPIC_API_KEY`, `WPJOBS_LLM`, `WPJOBS_LLM_MODEL` (`claude-haiku-5-5`), `WPJOBS_LLM_MAX_CALLS` (30).

All are listed in `packages/scrapers/coursejoiner/.env.example`.

## Decisions
- **REST first.** CourseJoiner's REST is open and fast: one light listing request per 100 posts, then content in `include=` batches of 25.
  - RSS has excerpts only, so it needs a page fetch per post. Sitemap `lastmod`s are stale (June 2026), so the HTML strategy is a last resort.
  - Conditional GET (ETag / If-Modified-Since) is used where servers support it (feeds, sitemaps). WP REST on these hosts sends no validators.
- **Category filter = include/exclude slug patterns** (`*` wildcards; exclude wins) plus a title guard for never-job posts (courses, Udemy, scholarships, quizzes, results, admit cards, answer keys, hackathons, job simulations, news like "X to hire 20,000"). Ambiguous categories (`program`, `fellowship`, `uncategorized`, `placement`) need a job word in the title.
- **A post counts only with company + role + external apply link.** If no link qualifies, the post is skipped.
  - Job-board links (Naukri, Internshala, LinkedIn, Indeed, Unstop) are accepted only when they point at a specific posting. Search and company pages are rejected.
  - Generic role fallbacks ("Intern", "Summer Intern", "Fellow") are used only when the post never names the role. That is rare (CashKaro, Akasa).
- **Apply-link preference**: company-matched ATS ≈ company careers deep link > generic company careers page > job-board posting > Google Form.
  - Company matching uses all company candidates (e.g. "FedEx" for "Federal Express Corporation"), against host labels and ATS tenants/paths.
- **Site picks**:
  - Replaced offcampusjobs4u.com, whose own robots section has `Disallow: /*?` and `/feed/`, with kickcharm.com.
  - Rejected freshersnow (govt/results; walk-ins with no apply link) and studentscircles (no longer WordPress).
- **LLM off** for sites whose robots.txt carries Cloudflare Content-Signals (none of the chosen four do, but `llm: false` exists for that).
- **Degrees** use a fixed vocabulary: B.E/B.Tech, M.E/M.Tech, BCA, MCA, B.Sc, M.Sc, BBA, MBA, B.Com, M.Com, BA, MA, B.Pharm, M.Pharm, LLB, B.Des, Diploma, ITI, PhD, CA, 12th Pass, 10th Pass, Any Graduate, Any Postgraduate.
  - BE/ME/BA/CA are matched case-sensitively or dotted, so the English words "be"/"me" never count.
- **Batches** only come from years next to batch words, because titles' "Internship 2027" is a season, not a batch. Category batches (`2025-batch`) are ignored, since freshershunt/kickcharm template them onto every post.
- **Tags** come from the title/role only (`off-campus`, `walk-in`, `wfh`, `urgent`, `women`). Site-wide categories like freshershunt's `off-campus-drive` on every post are not evidence. `wfh` also comes from specific slugs (`work-from-home`).

## Known gaps
- **Recycled post ids (fresheroffcampus).** It re-dates old posts with new content, so `<postId>#<n>` can mean a different job over time. The fingerprint follows `applyUrl`, so the DB still separates them, but the `(source, sourceJobId)` pair is reused. See the contract request.
- **Unresolvable shorteners.** `lnkd.in` links stay as-is (3 of 100 freshershunt jobs) because LinkedIn's robots.txt disallows bots. They still redirect for users.
- **CourseJoiner links job boards.** About 61% of its apply links are Naukri/Internshala/LinkedIn postings (the blog's own choice). These merge only with the same job-board record, not with an ATS record.
- **Generic careers landing pages** (e.g. `ea.com/careers`) are kept when they are the best link. Under fingerprint rule 1 they could collapse different jobs; see the contract request.
- **Fill rates are low where posts lack the field.** `validThrough`, salary and batches are rare on fresheroffcampus/kickcharm. Values are never invented.
- **Discovery slip.** Before reading offcampusjobs4u.com's full robots.txt (its own rules sit below a long Cloudflare-managed block), roughly a dozen REST/feed requests went to URLs its `Disallow: /*?` forbids, from my probes and an early version of `scripts/discover.ts`. The site was dropped, and `discover.ts` now only fetches URLs robots.txt allows.
- **pnpm 12** prints `ERR_PNPM_IGNORED_BUILDS` (esbuild) on `pnpm add` because the root workspace still uses `onlyBuiltDependencies`. It is harmless, since tsx/vitest work; P05 #1 has the fix for W1.

CourseJoiner run detail for the same 100 jobs:
- 200 posts listed; 121 job candidates; 115 parsed.
- Skipped: 75 excluded categories (courses, Udemy, scholarships…), 4 non-job titles, 3 without a role, 1 without an external apply link.
- 12 jobs were dropped because their deadline had passed.
- All tinyurl links were resolved.

Benchmarks:
- **Cold runs** (network for every listing, content batch and shortener, ≤ 1 req/s per host):
  - coursejoiner: 53 s for 100 jobs (2 listing pages, 3 content batches, about 40 tinyurl resolutions)
  - freshershunt: 20.5 s
  - fresheroffcampus: 12.3 s
  - kickcharm: 13.9 s
- **Warm runs** (cached content/parses): 2–3 s per site, about 11 s for all four. A steady-state incremental poll is one listing request per site.
- **Parsing**: 2.6 ms per post (≈ 390 posts/s) over 1,449 real posts.
- **Cache size**: 1.3–3.4 MB per site.

Tests: 137 offline tests pass. 4 live tests (`LIVE=1`, 5 jobs per site) also pass, in 38 s.
- Fixtures: 51 real post fixtures (26 CourseJoiner, 9 FreshersHunt, 7 FresherOffCampus, 9 KickCharm) with expected-RawJob file snapshots (`test/__expected__/`), plus a real RSS feed and a real post page.
- Shapes covered: single role, multi-role (anchors, role table, per-city links), Key-Highlights tables, KV lists, prose, internship, apprenticeship, walk-in, pool campus drive, WFH/remote, Google-Form registration, shortened links, the wrong-company link, and non-job posts that must be skipped (course, scholarship, hackathon, perks program, educational offer, news).
