# P04 · Company registry — contract requests & integration notes

Nothing in the frozen contract blocks the registry; everything below is optional and backward-compatible.

## 1. Requests (for W1)

1. **`CompanyTarget.aliases?: string[]`** — legal entities and former names ("Dreamplug Technologies" → CRED,
   "Bundl Technologies" → Swiggy, "One97 Communications" → Paytm). Today they live in `extra.aliases` and are also
   exported as `aliases` from `@easyjobs/registry`. A first-class field would let P03's `cleanCompanyName` and the API's
   company upsert use them without knowing about `extra`.
2. **Several boards per company.** Some companies run more than one live board (regional/legacy, or a portal plus an
   ATS). The registry keeps one target per company and lists the others in `extra.altBoards: [{ ats, token, openJobs }]`.
   If W1 wants to crawl them, either allow `CompanyTarget[]` entries with suffixed slugs (`acme`, `acme-eu`) or add
   `boards?: { ats, token }[]`.
3. **Greenhouse EU boards** (`job-boards.eu.greenhouse.io`, API `boards-api.eu.greenhouse.io`) have no token form in
   §0.6. Suggest the Lever convention: `eu:<token>`. None are in the registry today (detection keeps only US boards).
4. **Verification state.** `verifiedAt: null` + `extra.verifiedBy: "unverified"` marks entries whose official board
   exists but couldn't be fetched politely during verification (rate-limited / bot-protected). A contract-level
   `status?: "verified" | "pending"` would make that explicit for the worker.

## 2. Notes for consumers

- **P05 (worker)**: schedule only `ats` values that some scraper handles; `ats: "custom"` entries (≈ careers pages)
  exist for `findCompany()` tags/domains and for P09, not for scheduling. Priority 3 is also used for boards with
  0 open jobs. `getCompany(slug)` returns `null` (not `undefined`) when unknown.
- **P07 (public ATS)**: Ashby tokens are the board slugs from `jobs.ashbyhq.com/<slug>` **as URL path segments** —
  some contain `%20` (`Flock%20Safety`, `Hippocratic%20AI`; there is no space-free alias) and some are capitalised
  (the API is case-insensitive). Use them verbatim in the path; don't `encodeURIComponent` them again.
  SmartRecruiters tokens use the canonical identifier casing returned by the API (`SWIGGY`, `BoschGroup`).
  Workable returns `200 {"name":"Visa","jobs":[]}` for never-used account slugs — not a 404.
- **P08 (enterprise ATS)**:
  - Workday tokens are `https://<tenant>.wd<N>.myworkdayjobs.com/<site>` (locale stripped). `extra.workdayIndiaFacet:
    { parameter, id }` is the India facet value from the tenant's own facets — pass it as
    `appliedFacets: { [parameter]: [id] }` for an India-only crawl; `extra.indiaJobs` is that facet's count. `total`
    caps at 2000 on the CXS API; the registry's `openJobs` uses time-type facet sums above that.
  - **Workday is behind Cloudflare, and it starts answering 429 (an HTML challenge page) to Node's fetch from this
    machine after short bursts.** It began at 22:30 UTC, right after the registry's first probing burst (~2 req/s
    across tenants for under a minute, before its Workday gate existed), so that burst likely contributed to the block
    P08's runs hit too. It covered even `robots.txt` and was still active 80+ minutes later (other sessions also call
    Workday from this IP). curl from the same IP was unaffected, so it's client-fingerprint + IP scoring. We did **not**
    work around it. The registry now uses 1 request / 3 s and a circuit breaker for Workday; P08 should budget similarly.
    272 Workday entries are therefore `verifiedBy: "unverified"` until `pnpm --filter @easyjobs/registry verify` runs
    again while Workday answers.
  - Oracle tokens always use the `/en/` locale; Eightfold tokens are `https://<host>|<domain>`.
- **P09 (custom portals)**: the registry uses P09's slugs (`accenture`, `amazon`, `apple`, `atlassian`, `capgemini`,
  `cognizant`, `deloitte`, `ey`, `flipkart`, `google`, `hcltech`, `ibm`, `infosys`, `ltimindtree`, `meta`, `microsoft`,
  `tcs`, `tech-mahindra`, `uber`, `wipro`, `zoho`). Companies with an **enabled** P09 scraper are `ats: "custom"`
  (`extra.scrapedBy: "@easyjobs/scraper-bigtech"`) so the ATS adapters don't crawl the same jobs twice; any live ATS
  boards found for them (e.g. Accenture's Workday site) are listed in `extra.altBoards`. For the 6 disabled P09
  scrapers, a real ATS board is used when one exists. Keep `P09_PORTALS` in `scripts/verify.ts` in sync.
- **Root config**: `pnpm --filter @easyjobs/registry add …` exits with `ERR_PNPM_IGNORED_BUILDS` (esbuild) under
  pnpm 12 even though the root `pnpm-workspace.yaml` lists it in `onlyBuiltDependencies`; the install itself completes
  and tsx/vitest work. W1 may want the pnpm 12 equivalent (`pnpm approve-builds` / `allowBuilds`) in the root config.
- **Environment**: `NODE_TLS_REJECT_UNAUTHORIZED=0` is set in this machine's shell. Node's TLS verification works
  without it here, so the registry scripts were run with it unset; W1 may want to remove it from the environment.
