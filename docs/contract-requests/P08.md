# P08 · Contract requests (enterprise ATS scrapers)

Everything below is worked around today; nothing blocks P08.

## 1. Adopt the worker's run hooks (+1 to P05 #2)

P08 already calls `ctx.markIncomplete?.(reason)` and `ctx.report?.("blocked" | "partial", { reason, retryAt })`
when the worker provides them (single-target calls only), plus `ctx.report?.({ ...stats })` per target, and
falls back to throwing `IncompleteRunError` after yielding when they are absent. Reasons we need them:
- Workday's Cloudflare edge can challenge for 10–30 min: `report("blocked", { retryAt: +60 min })` stops
  the worker re-knocking (which lengthens the block) without counting a failure.
- Sitemap crawls with a per-run page cap and capped detail budgets are partial by design on first runs.

**Ask:** add both hooks to `ScrapeContext` in `@easyjobs/contract/node` (as P05 specified) and bump the version.

## 2. Let `isKnown` say whether the stored record has a description

`isKnown(id) → boolean` cannot tell a fully stored job from one first stored as a light record (detail
budget overflow with `*_OVERFLOW=light`, or a transient detail error). Such jobs never get a description.
P08 defaults to *deferring* over-budget unknown jobs for this reason, which delays big first runs.

**Ask:** `isKnown?: (id, target?) => boolean | "light"` (or `KnownIdsResponse.light?: string[]`), so
adapters can fetch details for known-but-light jobs within the budget.

## 3. Light-record marker (+1 to P05 #4)

P08 sets `extra.light = true` on every light record today. **Ask:** promote it to `RawJob.light?: boolean`
(P03 → `JobInput.extra.light`, API merge skips description-derived fields).

## 4. Headers on `HttpError`

`HttpError` keeps status and a body snippet but not headers, so `Retry-After` and `cf-mitigated` are lost
when using `http.json()`/`http.text()`. P08 uses `http.fetch()` with `retries: 0` and retries itself.
**Ask:** `HttpError.headers?: Record<string, string>` (at least `retry-after`, `cf-mitigated`), and do not
retry responses carrying `cf-mitigated: challenge` in `createHttpClient`.

## 5. Document per-source politeness keys

The contract client limits per *host*. Workday (`*.myworkdayjobs.com`) and Eightfold (`*.eightfold.ai` +
custom domains) throttle per client across all tenants. P08 keeps a process-wide gate per source family.
**Ask (docs):** note in `HttpClientOptions` that host-level limits are not enough for multi-tenant SaaS
platforms, and that adapters may add their own source-wide gates.

## 6. Registry token notes for P04 (guidance, no contract change)

- `oracle` tokens may be vanity URLs (`https://careers.ti.com/en/sites/CX`); P08 resolves them. Optional
  `extra.oracleApiBase` / `extra.oracleSiteNumber` skip that lookup.
- `eightfold` tokens should keep `|domain`; tenants are on two API generations (v2 / PCSX), detected
  automatically (`extra.eightfoldApi` forces one).
- `extra.workdayCountry` / `extra.country = "IN"` turns on India-only listing for Workday, Oracle and
  Eightfold — worth setting for MNCs with large non-India catalogues.
- Phenom/Radancy career sites (careers.adobe.com, jobs.thermofisher.com, jobs.boeing.com, jobs.citi.com)
  work as `phenom` / `jsonld`; Phenom records carry the underlying ATS apply URL, so registering the
  underlying Workday tenant as well is redundant but merges cleanly.
