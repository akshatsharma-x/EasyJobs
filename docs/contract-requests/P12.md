# Contract requests from P12 (open job APIs & feeds)

Everything below works today through `extra` or conventions; these requests would make it explicit for W1.

## 1. Per-source terms the web app must honour (high impact — legal)

Several APIs grant access on conditions that are about **display**, not scraping:

| Source | Condition |
|---|---|
| Remotive | Link back to the Remotive URL and name Remotive; **do not resubmit to Google Jobs, LinkedIn Jobs, Jooble…** |
| Himalayas | Apply button = `applicationLink` unchanged; visible link to Himalayas; **no JobPosting structured data / Google Jobs / feeds**; drop expired jobs |
| Remote OK | Link back to the Remote OK URL **without `rel="nofollow"`**; name "Remote OK"; don't use their logo |
| Jobicy | Credit Jobicy with a direct link; Apply = the feed URL |
| Adzuna | Label each ad "Adzuna" hyperlinked to adzuna.in |

Today: `Scraper.attribution` (string) + `RawJob.extra.terms` (`linkBackRequired`, `followLinkRequired`,
`applyUrlUnchanged`, `noJobPostingSchema`, `noThirdPartySyndication`, `creditRequired`, `noLogoUse`, `removeWhenExpired`).

Request:
- Add `attribution?: string` and `terms?: SourceTerms` to `JobSourceRef` (and `StatsResponse.sources`), with
  `SourceTerms` = the flags above, so the API can pass them to the web without reading `extra`.
- Web rule (W1/W2): emit `JobPosting` JSON-LD only when the job has an official source or no source with
  `noJobPostingSchema`; render source links with `rel="noopener"` (no `nofollow`) when `followLinkRequired`.
- Sitemaps/feeds (if any) must exclude `noThirdPartySyndication` sources.

## 2. Sweep semantics for feed scrapers

`RawJob.target` is documented as "feed key used for sweeps; null if not applicable", but `SweepRequest.target` is a
string and the worker sweeps per task. P12 convention: **non-null target = the run saw every open job of that feed**
(`remotive`, `whoishiring`, `unstop:jobs`, `unstop:internships`); **null = partial/windowed feed, never sweep**
(Adzuna, Jooble, Himalayas, Jobicy, Arbeitnow, Remote OK, WWR, The Muse).

Request: state this in §0.4 and have the worker sweep `(source, target)` for each distinct non-null `target` seen in a
complete run, and skip null-target jobs. Optionally add `Scraper.sweep?: "by-target" | "never"`.

## 3. Remote eligibility as a first-class field

P12 keeps only remote roles open to India or worldwide, and records `extra.remoteScope` =
`india | anywhere | asia | restricted | unknown` (HN posts keep all scopes). A typed `remoteScope` on RawJob/JobInput
would enable a "Remote — open to India" filter across all sources (ATS remote jobs are often US-only).

## 4. Generic careers URLs vs fingerprint rule 1

HN posts often list several roles with one shared link (`https://acme.com/careers`). With §0.4 rule 1 every role
would get the same `k:` fingerprint and collapse into one job, so P12 emits `applyUrl: null` (+ `extra.careersUrl`)
for such roles. Request: in `fingerprint`, apply rule 1 only when `canonicalJobKey` yields a job-specific key
(ATS job id, or a URL path with an id); for generic careers pages fall back to rule 2. Then P12 can always send the link.

## 5. Shared degree vocabulary

P12 maps Unstop course codes to: `B.E/B.Tech`, `M.E/M.Tech`, `BCA`, `MCA`, `B.Sc`, `M.Sc`, `BA`, `MA`, `B.Com`, `M.Com`,
`BBA`, `MBA`, `PGDM`, `Diploma`, `PhD`, `MBBS`, `B.Pharm`, `LLB`, `LLM`, … plus `Any graduate` and
`Any engineering course` / `Any management course` / `Any arts/science/commerce course` / `Any medical course` /
`Any law course`. Request: a `DEGREES` constant in the contract so P03/P10/P12 agree.

## 6. "Blocked" outcome for the circuit breaker

`SourceBlockedError` (exported by this package, `name === "SourceBlockedError"`) means an anti-bot wall (Cloudflare
challenge). Retrying soon is pointless and impolite. Request: a contract-level marker (e.g. `HttpError.blocked` or an
exported `SourceBlockedError`) so the worker pauses such sources for the full circuit-breaker window immediately.
