# P06 · CourseJoiner & job-blog scrapers — contract requests

Nothing here blocks P06: everything works under contract v1.0.0, and the workarounds use `extra` or local types. These are suggestions for W1. Items 1–2 agree with P05 #3 and #4.

## 1. `since` / `isKnown` semantics (contract docs) — agrees with P05 #3
`@easyjobs/scraper-coursejoiner` already behaves the way P05 describes:
- With `ctx.since`, it lists only posts modified after `since − 1 h` (WP `modified_after`). Such runs must never be swept.
- Without `since`, it re-emits the whole backfill window. Cached and known posts become light records, so they count as seen.

**Ask:** adopt P05's wording for `ScrapeContext.since` and `isKnown`.

## 2. Mark light records (contract) — agrees with P05 #4
Light records keep all hints (title, company, locations, jobType, level, batches, degrees, tags) and set `descriptionHtml: null`. They also carry **`extra.light: true`**.

**Ask:** make it `RawJob.light?: boolean`, so normalize/the API skip description-derived fields for these records.

## 3. Fingerprint rule 1 on generic careers pages (P03 / §0.4)
Blogs sometimes only link a company's careers landing page (`https://www.ea.com/en/careers/early-careers`, `https://www.infosys.com/careers/`). Rule 1 then makes `canonicalUrl(landing page)` the dedupe key, so every job that links the same landing page collapses into one.

**Ask:** apply rule 1 only when `canonicalJobKey` returns an ATS-specific id or the URL has a job-id-like segment. Otherwise use rule 2.
- To help, P06 sets `extra.applyLinkKind`: `ats` | `company` | `job_board` | `form` | `shortener` | `pdf` | `other`.
- It could also emit `extra.applyUrlSpecific: boolean` if P03 wants it.

## 4. Shared vocabularies (contract)
- **Degrees.** RawJob hints use this vocabulary: `B.E/B.Tech`, `M.E/M.Tech`, `BCA`, `MCA`, `B.Sc`, `M.Sc`, `BBA`, `MBA`, `B.Com`, `M.Com`, `BA`, `MA`, `B.Pharm`, `M.Pharm`, `LLB`, `B.Des`, `Diploma`, `ITI`, `PhD`, `CA`, `12th Pass`, `10th Pass`, `Any Graduate`, `Any Postgraduate`. **Ask:** a `DEGREES` const in the contract, so every scraper and normalize emit the same labels.
- **Walk-in fields.** Walk-in drives have a venue and interview date/time, which P06 puts in `extra.venue` and `extra.interviewDate`. **Ask:** optional `RawJob.venue?: string | null` and `interviewDates?: string[]` (ISO), if the UI wants to show them.

## 5. Recycled source ids (P02 merge)
fresheroffcampus.com re-dates old WordPress posts and replaces their content with a new opening under the same post id. So `(source, sourceJobId = <postId>#<n>)` can refer to a different job over time.
- The fingerprint follows `applyUrl`, so jobs stay separate.
- But "sources are unioned by (source, sourceJobId)" would attach one source row to two jobs.

**Ask:** when a known `(source, sourceJobId)` arrives with a different fingerprint, move the source row to the new job (and let the old job close if it has no other sources) instead of keeping both.

## 6. Per-scraper persistent state (contract, optional)
P06 keeps its parse/content/redirect cache in its own package directory (`.cache/`, overridable via `WPJOBS_CACHE_DIR`). That works on one host, but not on ephemeral or multi-instance workers.

**Ask:** an optional `ctx.state?: { get(key): Promise<string|undefined>; set(key, value): Promise<void> }` (worker-backed) for cursors and small caches. Large caches can stay on disk.

## 7. Root `pnpm-workspace.yaml` — same as P05 #1
pnpm 12 ignores `onlyBuiltDependencies`, so `pnpm add` exits with `ERR_PNPM_IGNORED_BUILDS` for esbuild. It is harmless, since tsx/vitest work. **Ask:** add `allowBuilds: { esbuild: true, sharp: true }`.

Note: `pnpm-workspace.yaml` no longer matches §0.2. pnpm 12's minimum-release-age policy added a `minimumReleaseAgeExclude` block (vitest 5.1.2, `@scalar/*`, hono) during some session's `pnpm add`; nobody edited it by hand. W1 should decide whether to keep it.
