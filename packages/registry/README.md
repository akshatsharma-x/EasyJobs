# @easyjobs/registry

A large, **verified** list of companies (`CompanyTarget[]`, prompts.md §0.6) with the exact ATS and token the
ATS scrapers need, plus a fuzzy `findCompany()` used by the worker/normalizer to attach company tags,
domains and slugs to jobs from any source.

```ts
import { companies, getCompany, targetsByAts, findCompany, matchCompany, aliases } from "@easyjobs/registry";

targetsByAts("greenhouse");                    // every verified Greenhouse board
targetsByAts(["workday", "oracle"]);           // several ATS types at once
getCompany("razorpay");                        // → { ats: "greenhouse", token: "razorpaysoftwareprivatelimited", … }
findCompany("Tata Consultancy Services Ltd");  // → TCS
findCompany("https://jobs.lever.co/cred/…");   // → CRED (ATS URLs resolve to the board's company)
findCompany("Dreamplug Technologies");         // → CRED (legal-entity alias)
matchCompany("Goldman Sach")?.via;             // → "fuzzy"
aliases["tcs"];                                // → ["Tata Consultancy Services", …]
```

- `companies` — frozen, sorted by slug, loaded from `data/companies.json` with `readFileSync` + `import.meta.url`.
- `findCompany(q)` — slug → ATS/careers URL → domain → name/alias → compact → core name → "known name + qualifier
  words" ("Amazon Development Centre (India) Pvt. Ltd.") → typo (bounded edit distance; ambiguous → `null`).
  Returns `null` rather than guessing. Results are cached; lookups are O(1) except the typo fallback.
- Also exported: `validateCompanyTarget`, `validateRegistry`, `isValidToken`, `TOKEN_RULES`, `detectAts`,
  `detectAtsFromUrl`, `normalizeName`, `coreName`, `namesMatch`, `createCompanyIndex` (build an index over any list).
  `@easyjobs/registry/ats` exposes the pure ATS fingerprint/token module on its own.

## Entry format

Standard `CompanyTarget` fields, tokens per §0.6. Conventions on top of the contract:

| field | meaning |
|---|---|
| `verifiedAt`, `openJobs` | time of the last successful check and the job count it returned (`null` for `custom`) |
| `priority` | 1 = Big Tech, Indian IT, India unicorns and other big India hirers (≈15 min) · 2 = other MNCs/startups that hire in India or remotely (hourly) · 3 = the rest **and any board with 0 open jobs** (daily) |
| `extra.verifiedBy` | `"ats-api"` — a live job API answered with a count (these are the "verified" boards) · `"ats-page"` — ATS identified (Phenom, SuccessFactors, Avature, iCIMS, Taleo, JSON-LD, Darwinbox, Keka, Zoho Recruit…) and its careers page loaded; no count API · `"careers-page"` — `ats: "custom"`, the company's own careers page loaded (P09 territory; the worker doesn't schedule these) · `"unverified"` — `verifiedAt: null`: the official board/portal is known (careers-page link or curated) but couldn't be reached politely (rate limit, robots.txt, bot wall); `extra.pendingReason` says why, and the next `verify` promotes it |
| `extra.scrapedBy` | `"@easyjobs/scraper-bigtech"` — P09 scrapes this company's portal; ATS boards we found are in `altBoards` |
| `extra.via` | how the board was found: `detect` (linked from the company's careers page), `hint` (curated), `probe` (slug probing, name/domain-matched), `workday-robots`, `eightfold-probe`, `previous` |
| `extra.evidence` | why we believe the board belongs to the company (`website linear.app`, `name "CRED"`, `job URLs on stripe.com`, …) |
| `extra.boardName` | company name as the ATS reports it |
| `extra.aliases` | legal entities / former names (also used by `findCompany`) |
| `extra.indiaJobs`, `extra.workdayIndiaFacet` | Workday only: India job count and the facet to pass as `appliedFacets: { [parameter]: [id] }` for an India-only crawl |
| `extra.altBoards` | other live boards seen for the same company (`[{ ats, token, openJobs }]`) |
| `extra.remote` | company hires remotely (incl. India) |

## Data files

| file | what |
|---|---|
| `data/companies.json` | the registry (generated by `scripts/verify.ts`, sorted by slug) |
| `data/rejected.json` | candidates without a verifiable board, with every proposal tried and why it failed |
| `data/summary.md` | counts by ATS, tag, priority, segment; top 50 by open jobs |
| `data/discovery/detect.json` | boards found on careers pages (committed so verify is reproducible) |
| `data/discovery/probe.json` | boards found by probing |

## Pipeline

```bash
pnpm --filter @easyjobs/registry candidates                      # stats of the curated list (scripts/candidates/*.ts)
pnpm --filter @easyjobs/registry detect razorpay.com             # one site → {"ats":"greenhouse","token":"razorpaysoftwareprivatelimited"}
pnpm --filter @easyjobs/registry detect --candidates             # all careers pages → data/discovery/detect.json
pnpm --filter @easyjobs/registry probe                           # slug probing → data/discovery/probe.json
pnpm --filter @easyjobs/registry verify                          # check every proposal → companies.json, rejected.json, summary.md
pnpm --filter @easyjobs/registry verify --only workday           # re-verify one ATS (everything else carried over)
pnpm --filter @easyjobs/registry verify --slug cred,swiggy --fresh
pnpm --filter @easyjobs/registry summary                         # regenerate summary.md
pnpm --filter @easyjobs/registry fixtures                        # refresh test/fixtures/html from the cache (no network)
```

1. **Candidates** (`scripts/candidates/*.ts`): ~1,900 companies in a compact `name | domain | tags | hq | flags | hints | aka`
   format (validated at load: tags ∈ `COMPANY_TAGS`, hint tokens per §0.6), merged by slug/domain.
2. **detect-ats**: fetches the careers page (robots.txt obeyed, ≤ 1 request/s per site, redirects followed), scans the
   redirect chain, HTML, inline scripts, one hop of job-listing links and a few first-party JS bundles for fingerprints of
   all 23 ATS types (`src/ats.ts`).
3. **probe**: slug variants (`name`, `name-hyphen`, domain stem, core name, then `namehq`/`nameinc`/`name-india`/`nameindia`)
   against the public Greenhouse/Lever/Ashby/SmartRecruiters/Workable/Recruitee APIs; Workday tenants via their
   `robots.txt` (which lists the career sites); Eightfold via `<tenant>.eightfold.ai`. A hit is kept only when the board's
   company name, website or job URLs match the candidate (`judgeBoard`): conflicting domain evidence beats a name match,
   and empty boards can't be matched on name alone (Workable answers 200 for never-used accounts like `visa`).
4. **verify**: per company, proposals are tried in trust order (careers-page link > curated hint > name-matched probe >
   page markers > Workday/Eightfold probes > previous entry > careers page as `custom`), each with the cheapest request
   that proves the board and counts jobs; a ≥ 5× bigger live board elsewhere wins. Transient failures keep the previous
   entry; real failures go to `rejected.json` with reasons.

| ATS | verification request |
|---|---|
| greenhouse | `GET boards-api.greenhouse.io/v1/boards/{token}/jobs` (`meta.total`) |
| lever | `GET api.lever.co/v0/postings/{token}?mode=json` (`api.eu.lever.co` for `eu:`) |
| ashby | `GET api.ashbyhq.com/posting-api/job-board/{token}` (listed jobs) |
| smartrecruiters | `GET api.smartrecruiters.com/v1/companies/{id}/postings?limit=1` (`totalFound`; 0 ⇒ unknown id) |
| workable | `GET apply.workable.com/api/v1/widget/accounts/{token}` |
| recruitee | `GET {token}.recruitee.com/api/offers/` |
| bamboohr / personio / breezy | `/careers/list` · `/xml` · `/json` |
| workday | `POST {site}/wday/cxs/{tenant}/{site}/jobs` with `limit: 1` (`total`; capped at 2000 by Workday, so facet sums are used above that) |
| oracle | `GET …/hcmRestApi/resources/latest/recruitingCEJobRequisitions?…finder=findReqs;siteNumber=…,limit=1` (`TotalJobsCount`) |
| eightfold | `GET {host}/api/apply/v2/jobs?domain={domain}&num=1` (`count`) |
| others / custom | the careers page loads (robots.txt obeyed) |

## Politeness

- Every request goes through `createHttpClient` (robots.txt, per-host spacing, retries with backoff) with the
  `SCRAPER_USER_AGENT`. `robots: false` only for the documented public job APIs above.
- On top of that, a per-ATS gate (≤ 4 in flight; Workday 1 at a time ≥ 3 s apart, Workable/Oracle/Eightfold 2 at a time)
  and a circuit breaker: on 429 the whole ATS family cools down for 10 min, after 3 strikes it isn't called again that run
  (reported as a transient error, never as a dead board). A careers site answering 429 is skipped for the run.
- jobs.ashbyhq.com disallows `/api/` in robots.txt, so the Ashby GraphQL API is never used — names come from the public
  board page instead.
- Responses are cached in `.cache/http` (≤ 3 MB bodies) and check results in `.cache/checks` (20 h TTL; `--fresh` bypasses).

## Env

| var | default | used for |
|---|---|---|
| `SCRAPER_USER_AGENT` | `EasyJobsBot/1.0 (+https://easyjobs.example/bot)` | all requests |
| `LOG_LEVEL`, `LOG_FORMAT` | `info`, pretty | script logs |

No other configuration; the library itself never touches the network.

## Adding a company

Add a line to the right file in `scripts/candidates/` (a hint like `gh:token` or `wd:https://…` if you know the board),
then `pnpm --filter @easyjobs/registry verify --slug <slug>` (run `detect --candidates --slug <slug>` and/or
`probe --slug <slug>` first if you don't know the board), and `pnpm --filter @easyjobs/registry test`.
